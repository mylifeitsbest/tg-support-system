# Как начать работу

Короткий гайд. Если непонятно — спросите агента в Cursor: «помоги по онбордингу».

> В Cursor по возможности выбирайте **Cursor Grok 4.5 high (не Fast)**.

---

## Первый запуск (один раз)

1. Скопируйте этот starter в свой репозиторий (см. README).
2. Откройте папку проекта в Cursor.
3. Создайте ветку `dev`, если её ещё нет.
4. Создайте GitHub Project с канбаном и заполните `CHANGE_ME` в
   `scripts/agent/board.sh` / `board.ps1`.
5. Создайте свой GitHub token (scopes `repo` + `project`) и войдите:
   ```bash
   gh auth login
   gh auth refresh -s project
   ```
6. Заполните `AGENTS.md`, `project-atlas` и code-style/verify под свой стек.

Готово: можно работать.

---

## Ежедневный цикл

Задачи — **GitHub Issues** (название вида `[ 42 ] Починить логин`).

| Команда | Что происходит |
| --- | --- |
| `/pplan 42` | План в issue, карточка → Ready. Код не трогает. |
| `/work 42` | Назначает на себя, ветка, реализация. Не начнёт при открытом блокере. |
| `/verify 42` | Проверки. Доску не трогает. |
| `/ship 42` | Пуш в `dev`, карточка → Done. |
| `/do-all 42` | Мелкий срочный фикс: весь цикл сразу. |

Один тикет — можно вести в одном чате. Новый чат — когда переходите к другой задаче.

Ветки простыми словами:

- **своя ветка** — черновик одной задачи;
- **`dev`** — общий стол: код уже в репо после `/ship`.

Не пушьте мимо `/ship`: скрипт специально не пускает непроверенное.

---

## Чего делать нельзя

- Коммитить `.env`, токены, ключи.
- Писать секреты в чат или issues.
- Смешивать в один коммит чужие незакоммиченные файлы.
- Плодить сверхмелкие тикеты или сваливать полпроекта в один.
